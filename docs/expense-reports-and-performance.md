# 지출·정산 보고서와 최적화 (2026-11-09)

## 사용
- 여행이 종료돼도 가계부와 여행 후 정산 페이지에서 내역을 추가·수정하고 정산할 수 있습니다. 날짜/상태에 따른 잠금이나 자동 삭제를 추가하지 않았습니다.
- 개요 메뉴, 가계부, 여행 후 페이지의 ‘지출·정산 보고서’에서 현재 기록을 다시 생성합니다.
- 실제 결제 원금, 참여자 분담액, 기록된 중간정산 송수금, 상계 후 남은 송금안을 통화별로 분리합니다.
- CSV 다운로드와 브라우저 인쇄/PDF 저장을 지원합니다. CSV의 문자열 수식 실행, 따옴표와 개행을 처리합니다.
- 정산 테이블 SQL을 아직 적용하지 않았거나 읽기에 실패하면 지출은 보여주되 정산/분담액은 미확인으로 표시합니다. 기존 `supabase/settlement-records.sql` 적용은 여전히 필요합니다.
- 지출에 연결되지 않은 과거 전체 정산 기록을 임의로 지출에 배분하지 않습니다. 전체 차액에는 반영하고 별도 안내합니다.
- 참여자별 묶음은 같은 지출을 여러 그룹에 표시할 수 있습니다. 그룹 금액은 원금이며 개인 분담액은 보고서에서 확인합니다.

## 점검 및 개선
- 여행 메타데이터 조회: 전체 데이터 대신 `view=meta`를 사용합니다. 같은 계정·같은 여행의 동시 요청만 합치고 응답을 전역에 영구 보관하지 않습니다.
- 가계부와 정산 팝업: 동일한 정산 데이터와 변경 함수를 공유해 팝업을 열 때 중복 GET을 없앴습니다.
- 실시간 구독: 서버가 해석한 여행 UUID를 응답에 포함하고 현재 여행/현재 뷰의 관련 테이블만 구독합니다. 연속 이벤트를 200ms로 묶고 페이지 이동 시 예약된 갱신을 취소합니다. 이전 페이지 요청의 늦은 응답도 무시합니다.
- 정산 계산: 지출별 분담과 송금 기록을 ID로 한 번 인덱싱해 지출마다 전체 기록을 다시 탐색하지 않습니다.
- 가계부: 필터 결과를 메모이제이션해 입력 폼의 키 입력이 정렬/그룹 계산을 다시 유발하지 않도록 했습니다.
- 여행 목록 캐시: 동시 요청은 공유하고 성공 결과는 30초 만료, HTTP 실패는 재시도합니다. 계정 전환 및 여행 수정/삭제 시 무효화합니다. 오래된 요청 실패가 새로운 캐시를 삭제하지 않게 했습니다.

## 검증과 한계
- 메타데이터 조회의 테이블 읽기 14개 → 1개 확인(공통 slug 해석 비용 제외).
- 로컬 합성 데이터: 지출/분담/정산 기록 각각 1,500개, 3회 중앙값 약 75ms → 50ms. 최적화 전후 결과 JSON 동일. 운영 환경의 응답 시간이나 전체 앱 속도를 보장하는 수치는 아닙니다.
- 타입 검사, 정산 금액 보존/부분정산/완료/취소, 지출 API, 보고서/CSV/인증/여행 범위/SQL 미적용, 메타데이터 중복 요청/실시간 구독/캐시 테스트 통과.
- 375px 로컬 fixture로 요약 조회, 접힌 정산 상세, 보고서 가로 넘침 없음을 확인했습니다. 실제 운영 사용자 데이터는 테스트에 사용하지 않았습니다.
- 의존성 업그레이드, 무관한 파일 재작성, 사용자 로컬 준비물 변경이나 복제 파일 정리는 수행하지 않았습니다.
